# Веб-морда пайплайна

Self-hosted страница поверх ЛЛМ-петель: выбрать деталь, вид обработки и
параметры, нажать кнопку — и смотреть, как петля крутится, пока не получится
деталь.

```bash
python -m web.server --port 8080 --llm openrouter --llm-model deepseek/deepseek-v4-flash-0731
```

Открывается на `http://localhost:8080`. Сервер слушает `127.0.0.1` — наружу
ничего не торчит; `--host 0.0.0.0` пускает в локальную сеть, если это нужно.

## Что на странице

**1. Деталь.** Два поля выбора файла — модель детали (обязательно) и
заготовка. Обычный проводник ОС, плюс drag-and-drop. Форматы: STEP, IGES,
BREP, STL, OBJ и NX `.prt` (конвертируется автоматически, если NX установлен).

**2. Вид обработки — ФРЕЗЕРОВКА или ТОЧЕНИЕ.** Выбирается в браузере, потому
что это свойство ДЕТАЛИ: тело вращения точат, корпусную деталь фрезеруют. От
выбора зависит всё дальнейшее — параметры, этапы, петля:

| | Фрезеровка | Точение |
|---|---|---|
| петля | `auto_fix.py` | `auto_fix_lathe.py` |
| что правит агент | параметры резания, зоны, инструмент операции | НАБОР ИНСТРУМЕНТА |
| заготовка | файлом или боксом от габарита | прокат по ГОСТ, подбирается сам — поле файла прячется |
| приёмка | объём: зарез 0, недорез < 1 мм³ | ДОПУСК ПО РАДИУСУ (по умолчанию 0.12 мм) |
| симуляция за итерацию | одна | две — оба установа, плюс сборка итога |
| итерация | 3–5 минут | ~6 минут |

**3. Параметры.** Разделы у обоих видов ОДНОИМЁННЫЕ — инструмент, черновая,
заготовка, режимы станка, проверка, петля — чтобы страница читалась одинаково;
содержимое, разумеется, своё. **Значения подставлены из `config.py`** — не
продублированы, а прочитаны в момент открытия страницы, так что форма всегда
показывает то же, с чем работает CLI. Менять нужно только то, что нужно:
параметр, который не тронули, в конфиг задачи не попадёт и возьмётся из
дефолтов.

**Раздел «Инструмент» у точения устроен иначе** — там не числа, а НАБОР.
Список — весь парк цеха (`lathe/lathe_tools.py`), галочками отмечается, что из
него выдано генератору. Роли — кто ведёт черновую, кто чистовую, кто лезет за
уступ — генератор выводит сам из геометрии выданного, а агент в петле меняет
ровно этот набор и ничего больше. Ссылки «все / снять» рядом с заголовком:
набор перебирают пачками, не по одной галочке.

**4. Кнопка.** Запускает петлю своего вида и показывает её ход.

## Что видно во время работы

Крупно — текущий этап и счётчик итераций, схема процесса, таймер. Схема
рисуется по этапам своего вида: у фрезеровки в цикле одна симуляция, у точения
две (`ISV установ 1` → `ISV установ 2`) и сборка итога. Ниже — таблица
расхождений по итерациям и лента событий. Галочка «показывать весь лог»
открывает сырой вывод FreeCAD и NX — по нему видно, что процесс жив, когда
симуляция идёт третью минуту.

Прогресс идёт по SSE (`/api/jobs/{id}/events`). Страницу можно закрыть и
открыть заново — она подхватит текущую задачу и досмотрит её с начала ленты, в
том числе нарисует схему по виду обработки ЗАДАЧИ, а не выбранного в форме.

## Результат

Список файлов на скачивание, браузер сам спросит, куда сохранить.

Фрезеровка:

| файл | что это |
|---|---|
| `*_compare.prt` | **деталь и результат слоями — это открывать в NX** (слой 1 модель, слой 2 что вырезалось) |
| `*_sim.stp` | результат симуляции отдельным телом |
| `*.gcode` | управляющая программа |
| `*_part.step`, `*_stock.stp` | деталь и заготовка в координатах программы |
| `*_diff.json`, `*_autofix.json` | сверка по зонам и журнал итераций |

Точение:

| файл | что это |
|---|---|
| `out_full.step` | **ИТОГ обоих установов, солид** — накладывать на `out_part.step` |
| `out_part.step` | деталь в координатах программы, эталон для наложения |
| `out.gcode`, `out_2.gcode` | программы первого и второго установа |
| `out_nxdiff.md` | сверка по поясам: отклонение по радиусу, с поправкой на плёнку |
| `out_setup1_nxsim.stp`, `out_setup2_nxsim.stp` | результаты ISV по установам |
| `out_nxdiff.json`, `out_loop.json` | сверка целиком и журнал итераций с ответами агента |

## Устройство

```
web/
  server.py    FastAPI: маршруты, SSE, отдача статики; CLI запуска
  jobs.py      запуск петли подпроцессом, разбор её вывода в события
  params.py    какие параметры показывать, границы и подписи
  static/      index.html + app.js + style.css, без сборки и без npm
```

Всё, что различает виды обработки, собрано в таблицах: `params.MILL_SPEC` /
`LATHE_SPEC` (что показывать), `jobs.PHASES` / `RULES` / `OUTPUTS` (этапы, разбор
лога, файлы результата) и `jobs._command` (чем запускать). Остальной код общий.

Почему так:

**FastAPI, а не Streamlit/Gradio.** Пайплайн на Python, значит бэкенд читает
`config.py` напрямую и не дублирует дефолты. Прогресс — односторонний поток
событий, для него хватает SSE. Фронт без сборки: один HTML, один JS, один CSS —
на машине с NX не нужен ни npm, ни node.

**Петля запускается ПОДПРОЦЕССОМ, а не импортом.** Петля правит глобальный
`config`; в одном процессе с сервером это протекло бы между задачами. Плюс
зависшую задачу можно убить, не роняя сервер.

**Одна задача за раз.** NX берёт лицензию, FreeCAD и симуляция занимают машину
целиком. Вторая задача параллельно не ускорит, а сорвёт обе — попытка запустить
вторую возвращает 409 с объяснением.

**Прогресс парсится из stdout петли.** Она уже печатает осмысленные вехи
(`[autofix]`, `[loop]`, `[worker]`, `[lathe-sim]`), и парсер — небольшая таблица
шаблонов. Тонкость: петля объявляет этап, когда он ЗАКОНЧИЛСЯ («G-Code: 7205
строк»), а показывать надо идущий сейчас, поэтому парсер устроен автоматом:
увидел конец генерации — значит пошла симуляция.

**Токарная петля запускается с `--stream`.** Вехи прогона печатает не она, а
`run_lathe.py`, и по умолчанию они уходят только в файл `run_itN.log`. Без
пересылки страница пять минут показывала бы «генерация», пока идут два прогона
в ISV. Флаг добавлен ради этого и на поведение CLI не влияет.

**Агент выбирается при запуске сервера**, а не в браузере: это настройка
установки, а не параметр детали. Наличие ключа проверяется сразу, иначе
пользователь узнал бы о его отсутствии через пять минут работы NX.

## Грабли

- **Подпроцесс запускается через `sys.executable`**, а не `python`: в PATH этой
  машины другой интерпретатор, без `pyyaml`, и петля падала на первой же строке
  чтения конфига.
- **Имя загруженного файла санируется, расширение сохраняется.** Расширение
  решает всё: по нему пайплайн выбирает читатель, а `.prt` уходит на
  конвертацию через NX. Кириллицу и пробелы убираем — FreeCAD и OCCT не
  открывают такие пути.
- **`hidden` обязан побеждать стиль.** У `.file` свой `display:block`, а
  `[hidden]` в браузерном стиле слабее по специфичности — поле заготовки
  оставалось на странице при выборе точения. В CSS стоит
  `[hidden]{display:none !important}`.
- Прогоны складываются в `runs/web/<дата-время-id>/` вместе с `cfg.yaml`,
  `cmd.txt` и `web.log`: любой прогон повторяется руками той же командой.

## Чего в морде намеренно нет

- **Порогов приёмки фрезеровки** (`DIFF_OK_*`): их двигает петля, и мешать «как
  резать» с «что считать годным» в одной форме нельзя. У точения приёмка другая
  по природе — это допуск по радиусу с чертежа, его технолог задаёт сам.
- **Мёртвых зон, доп. зон и отключения операций**: это координаты и имена
  операций, их заполняет агент по ходу петли.
- **Резьбы** (`LATHE_THREADS`): из модели шаг не выводится в принципе (CAD несёт
  гладкий цилиндр, шаг знает только чертёж), а объявлять её списком словарей в
  веб-форме — это не форма, а YAML.
- **Путей к FreeCAD и NX**: машинные настройки, им место в `config.yaml`.
- **Выбора агента в браузере**: см. выше.
