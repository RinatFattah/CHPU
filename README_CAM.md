# CAM: CAD-модель → G-Code (FreeCAD)

Получение траектории обработки **по готовой модели детали**, без LLM и Blender.
Вход — CAD-файл, выход — управляющая программа (G-Code) для станка с ЧПУ.
Стратегия — **3D-обработка по поверхности**: фреза следует за фактической геометрией
модели (наклоны, конусы, купола, рельеф).

```
деталь.prt (Siemens NX) ──► python run_cam.py деталь.prt ──► деталь.gcode
                              │ 1) NX (headless): .prt → STEP AP242
                              │ 2) FreeCAD Path/CAM (headless): STEP → G-Code
деталь.step ─────────────────► сразу шаг 2
```

## Форматы входа

| Формат | Как читается | Рекомендация |
|---|---|---|
| `.step` / `.stp` | точное твёрдое тело (BREP), единицы из файла | ✅ **основной вход** |
| `.iges` / `.igs`, `.brep` | точное тело | ✅ да |
| `.stl` / `.obj` | меш → фасеточное тело (аппроксимация) | допустимо, хуже точность |
| `.prt` (Siemens NX) | конвертируется в STEP штатным транслятором NX (нужен установленный NX; версия протокола — `NX_STEP_AP`, дефолт AP242) | ✅ да, при наличии NX; без NX — экспортируйте STEP вручную |

## Быстрый старт

```bash
python run_cam.py detal.step                          # черновая по этапам
python run_cam.py detal.step out.gcode --config config.yaml
python run_cam.py detal.step --stock-margin 0         # заготовка точно по детали
python run_cam.py detal.step --stock otlivka.step     # заготовка из файла (отливка)
python run_cam.py scan.stl --mm                       # меш в миллиметрах
python run_cam.py detal.prt                           # .prt напрямую (нужен NX)
```

Флаги CLI: `--config FILE`, `--rough MM` (величина припуска), `--allowance-xy` /
`--allowance-all` (где оставлять припуск; без них — начисто),
`--stock-margin MM`, `--stock FILE`, `--stock-align` (выровнять заготовку по детали:
X край в край, Y центр, дно в дно — когда один файл заготовки на серию деталей),
`--origin ...`, `--no-orient`; для мешей — `--mm` / `--meters` /
`--scale N` (STEP/IGES масштаб не нужен — единицы в файле).

## Как строится обработка

Черновая идёт **по этапам, как у технолога** — отдельными операциями в порядке
техпроцесса, зоны не пересекаются (фреза не проходит одно место дважды):

1. **RoughHole1..N** — **сквозные вырезы любой формы**, по очереди от ближнего
   к дальнему, **первыми** (пока деталь ещё жёстко держится в заготовке). Вырез =
   внутренний замкнутый контур силуэта (круглый, овальный, фигурный — не важно),
   режется одной зоной адаптивной выборкой. Куда фреза с припуском не влезает —
   пропуск с сообщением в лог.
2. **Грани сверху вниз** — по одной операции на грань, самые высокие первыми,
   плоские и наклонные **вперемешку по высоте**. Берутся только **достижимые
   сверху** грани: над гранью есть материал заготовки, грань смотрит вверх (есть
   проекция на XY), и над ней **нет тела детали** (не накрыта, не нависание):
   - плоские (полки, донья карманов, уступы) — **RoughFace1..N** адаптивной
     выборкой, глубина = высота грани + припуск;
   - наклонные/криволинейные (скос, купол, радиус гиба) — **RoughSlope1..N**
     «террасами»: фреза следует за поверхностью слоями `ROUGH_STEPDOWN`, держась
     на `ROUGH_ALLOWANCE` выше неё; ступеньки на наклоне остаются (чистовой
     обработки нет — только черновая).
3. **RoughPerimeter** — **внешний контур детали по силуэту, последним**: один
   обвод фрезой снаружи (Path Profile, отступ радиус + припуск по стенке, слоями
   до дна детали). Обвод начинается **с верха нижней полки** детали (самая
   большая горизонтальная грань, смотрящая вверх), а не с верха заготовки: выше
   полки силуэт сжимается до стенки, и обвод шёл бы там по воздуху — лишние
   минуты на каждый слой.
   Контур режется в самом конце — пока идёт внутренняя обработка, деталь жёстко
   держится в «рамке» заготовки. **Лишний материал в углах заготовки, не
   касающийся детали, остаётся** — прорезается только периметр детали, а не всё
   поле (в этом режиме широкие поля `STOCK_MARGIN` бокс целиком не выбирают).

Чего черновая сознательно НЕ делает: **недоступное сверху** (грани, смотрящие
вниз/вбок, материал под нависающими элементами, накрытые грани) — это второй
установ, программа честно его пропускает (площадь печатается предупреждением),
а не режет сквозь деталь.

Вырезы и плоские грани — адаптивная выборка (FreeCAD Path Adaptive) слоями
`ROUGH_STEPDOWN`; припуск — по режиму `ROUGH_ALLOWANCE_MODE` (дефолт `none` = начисто; `--allowance-xy` = стенки; `--allowance-all` = везде); наклонные —
проход по поверхности (Path Surface, Multi-pass); внешний контур — Path Profile.
Чистовой проход отсутствует — на выходе только черновая по этапам.

**Экспериментальный режим `--rough-mode layers`** (`ROUGH_MODE: "layers"`) —
послойная черновая, как Cavity Mill в NX: материал на высоте Z = сечение
заготовки − тень детали выше Z. Высоты делятся на диапазоны между характерными
уровнями детали (наклонные участки дробятся по `ROUGH_STEPDOWN`), соседние
диапазоны с одинаковой зоной склеиваются, каждая связная область — отдельная
операция (`B<N>Contour`/`B<N>Pocket`, сверху вниз, на уровне — от ближней).
Ничего не предполагает о форме детали и заготовки, поэтому устойчивее к
нестандартным заготовкам (уголок, отливка) и обычно быстрее по машинному
времени; этапный режим остаётся дефолтом.

**Заготовка** — два варианта:
- **бокс** (по умолчанию): габарит детали + поля (`STOCK_MARGIN` по X/Y,
  `STOCK_MARGIN_TOP` сверху);
Какой бы ни была заготовка, рядом с G-Code сохраняется `<имя>_stock.stp` —
заготовка **в координатах программы** (повёрнутая и сдвинутая вместе с деталью,
ноль — как в G-Code): её можно грузить в симулятор или использовать при наладке.

- **произвольная из файла** (`STOCK_FILE` / `--stock FILE`, форматы те же, что
  у модели): отливка, поковка, обрезок. Файл должен быть **в той же системе
  координат, что и модель детали** (например, оба экспортированы из одной
  сборки NX) — заготовка автоматически поворачивается и сдвигается синхронно
  с деталью. Зона контура при этом строится от реального силуэта заготовки.
  Если деталь выступает из заготовки — предупреждение в лог.
  Заготовка не обязана иметь ровный верх (уголок, отливка): каждая операция
  сама находит локальный верх материала над своей зоной и начинает резать
  оттуда, а зоны, над которыми материала нет, пропускаются. Материал над
  самым верхом детали тоже снимается; узкие верхние полки (уже фрезы)
  обрабатываются террасами по поверхности.

Размеры заготовки, детали и инструмента печатаются в лог и в шапку G-Code
комментариями (`(Stock: ...)`, `(Part: ...)`, `(Tool: ...)`; координаты бокса —
в нуле программы, удобно копировать в настройку заготовки CAMotics).
Инструмент — один на программу: плоская концевая фреза `TOOL_DIAMETER`.

## Параметры генерации G-Code

Задаются в `config.yaml` (копия `config.example.yaml`) или в `config.py`.
Приоритет: дефолты → YAML из `--config` → флаги CLI.

### 1. Инструмент и режимы резания — задать ОБЯЗАТЕЛЬНО под свой станок/материал

| Параметр | Дефолт | Ед. | Что означает |
|---|---|---|---|
| `TOOL_DIAMETER` | `6.0` | мм | диаметр фрезы. Для криволинейных поверхностей желательна **сферическая (ball-nose)** — плоская оставляет ступеньки между строчками |
| `FEED_RATE` | `2000` | мм/мин | рабочая подача; вертикальная врезка автоматически = 1/4. 2000 — заводское значение: `PR_1_01…06` режут на нём при тех же 12000 об/мин и той же фрезе Ø12 |
| `SPINDLE_SPEED` | `12000` | об/мин | обороты шпинделя (M3 S…). Могут переопределяться НА ОПЕРАЦИЮ из техплана: завод режет окно 003 на 7984 (301 м/мин) против 12000 (452) на остальном — это единственное место с полным зацеплением фрезы |
| `MATERIAL` | `""` | — | марка обрабатываемого материала, например `Д19чТ`. На расчёт не влияет, идёт в техплан и включает проверку предела `t×B` по нужной колонке норматива |
| `MACHINE` | `""` | — | модель станка, например `DMC-635V, iTNC530`. Только в техплан |
| `PLAN_IN` | `""` | путь | входной техплан (`--plan`): состав операций, инструмент, слой, шаг строчек и режим берутся из него, а не из эвристик. Пусто — обычный режим |
| `SAFE_HEIGHT` | `10.0` | мм | высота над заготовкой для холостых перемещений |

### 2. Заготовка

| Параметр | Дефолт | Ед. | Что означает |
|---|---|---|---|
| `STOCK_MARGIN` | `12.0` | мм | поля заготовки вокруг детали по X и Y. Дефолт = 2 диаметра фрезы (при таких полях контур выбирается адаптивно). `0` = заготовка по габариту детали, контур — одним проходом вокруг силуэта (углы, выступы) |
| `STOCK_MARGIN_TOP` | `0.0` | мм | запас материала над деталью (Z+) |
| `STOCK_FILE` | `""` | — | заготовка из файла (`--stock`), включая `.prt` при наличии NX; пусто = бокс. Файл в той же системе координат, что и модель; `STOCK_MARGIN` игнорируется |
| `STOCK_ALIGN` | `false` | — | выровнять заготовку из файла по детали (`--stock-align`): X край в край, Y центр, Z дно в дно — когда один файл заготовки на серию деталей |
| `FLOOR_CLEARANCE` | `0.5` | мм | зазор от стола: фреза не опускается ниже «дно детали + зазор» ни в одной операции (сквозные вырезы и контур оставляют плёнку) |
| `TOOL_SET` | `[12]` | мм | набор фрез (по убыванию) — многоинструментальность: воркер назначает каждой операции крупнейшую влезающую (крупная — выборка/контур, мелкая — узкие места). **Дефолт с 22.08.2026 — ОДНА фреза**, по замечанию ОЭЦМ КнААЗ («в обучающей выборке один инструмент D12, оптимальный для детали данного типа»); прежний набор `[12, 4, 1, 0.4]` заводил Ø0.4, которой на этих деталях никто не работает. Цена: узкие места, куда Ø12 не влезает, остаются необработанными — сверка покажет недорез. Добавьте диаметры сюда, и G-код получит смены `T1/T2/…`, а симуляция NX — таблицу стойки на все фрезы |
| `SET_OP_TOOLS` | `{}` | — | пофрезное переопределение: `{RoughSlope2: 3.0}` — диаметр для конкретной операции (вручную или из `auto_fix.py`, действие `set_op_tool`). Диаметр берётся **как есть**: перечисленные фрезы добавляются в набор, даже если их нет в `TOOL_SET` |
| `DEAD_ZONES` | `[]` | — | запретные XY-боксы в координатах программы (`[{x: [a, b], y: [a, b]}]`) — фреза туда не заходит; заполняется вручную или ЛЛМ-петлёй `auto_fix.py` |
| `EXTRA_ZONES` | `[]` | — | дополнительные зоны съёма (`[{x, y, z_bottom}]`) — принудительная дообработка недорезов (ExtraZone<N>); вручную или через `auto_fix.py` |
| `SKIP_OPS` | `[]` | — | имена операций, которые не создавать (`["RoughSlope2", …]`) — если конкретная операция вредит; вручную или через `auto_fix.py` |

### 3. Черновая обработка

| Параметр | Дефолт | Ед. | Что означает |
|---|---|---|---|
| `BULK_ROUGH` | `true` | — | съём объёма НАД деталью отдельной первой стадией (`RoughBulk<N>`), уровнями по `ROUGH_STEPDOWN`. Так устроена заводская программа: у детали 003 половину всего рабочего хода завода занимает операция `NK_1_01`, которая сносит лишнюю часть стоячей полки уголка, а всё остальное работает уже по остатку. Без стадии её работу делают операции по граням, каждая заново проходя весь столб материала над собой (на 003 это 19 058 мм из 22 427). Узкая зона (средняя ширина < 2 Ø) обходится контуром, широкая выбирается Adaptive |
| `CLEAR_CONTOUR_BAND` | `true` | — | очистка полосы под обвод контура отдельной стадией (`RoughClear<N>`), сразу после съёма объёма. Обвод режет на уровне полки, а тело фрезы поднимается на всю длину режущей части: стоит в её следе заготовка — фреза снимет её БОКОМ, на всю высоту и на подаче под съём слоя, а сверка этого не покажет (она меряет тело детали). Зона считается: след обводной фрезы (кольцо от нуля до 2R + припуск вокруг силуэта) ∩ сечение ЗАГОТОВКИ выше старта обвода; путь — сам путь обвода, обрезанный участками со стоящим материалом. Линий две — полоса шире фрезы ровно на припуск. Где ничего не стоит, операций не создаётся |
| `CLEAR_STEPDOWN` | `0` | мм | слой очистки; 0 = как `ROUGH_STEPDOWN`. Отдельный параметр потому, что очистка режет ЛОМ: шероховатость не важна, радиальная нагрузка ограничена толщиной стоящей стенки. На 003 слой 3 мм вместо 1 мм — это 00:05:31 вместо 00:07:22 при той же сверке 0/0 |
| `CLEAR_THIN_PASS` | `10.0` | мм | граница «фреза ПЕРЕСЕКАЕТ кусок»: толщина куска ВДОЛЬ ХОДА не больше этой — берётся крупный `CLEAR_STEPDOWN_SHALLOW`, больше (фреза идёт вдоль металла, контакт длинный) — осторожный `ROUGH_STEPDOWN`. Считается по каждому куску отдельно; направление хода — самое длинное прямое ребро пути, иначе хорда цепочки. Работает только при `CLEAR_STEPDOWN = 0`. На 003 куски у торцов стенки — 4.4 мм вдоль хода, шаг 1.5 как у завода: 19 уровней → 13, 1 401 → 958 мм рабочего хода и −1.4 м холостого при сверке 0/0. Прежнее имя `CLEAR_TALL_BAND` мерило ВЫСОТУ полосы — другой вопрос; алиаса нет, старый ключ конфига печатается как неизвестный |
| `CLEAR_STEPDOWN_SHALLOW` | `1.5` | мм | слой для невысокой полосы — заводское значение (`NK_1_02/03` идут по 1.5 при тех же F2000 и 12000 об/мин) |
| `CLEAR_STRAIGHT` | `true` | — | прямые проходы вдоль куска вместо куска контурной кривой. Путь обвода прямой не везде: у угла детали он уходит дугой радиуса R + припуск, и обрезка его зоной достижимости тащит дугу за собой — снимать там нечего, зато каждый уровень длиннее, а вход попадает туда, где под фрезой стенка САМОЙ ДЕТАЛИ, то есть требует врезания рампой. Применяется, только когда кусок — прямоугольник в осях прохода и следы фрез накрывают его целиком; иначе поведение прежнее, обвод по контуру. На 003: 2 566 → 1 400 мм рабочего хода на стадии, рампы исчезли |
| `FILLET_PROFILE` | `true` | — | скругление ВДОЛЬ РЕБРА резать ходом ПО СЕЧЕНИЮ, а не 3D-проходом сверху. Признак берётся из модели: грань — цилиндр с ГОРИЗОНТАЛЬНОЙ осью и телом со стороны оси (выпуклый угол); цилиндры с вертикальной осью (углы полки, окна) и свободные формы идут прежним путём. Путь считается формулой «плоская фреза катится по цилиндру»: дуга радиуса R, сдвинутая на радиус фрезы по горизонтали; шаг строчек вдоль ребра — по гребешку `d = sqrt(2*R_ф*h - h^2)` (кромка фрезы отходит от детали по окружности, одной строчкой у краёв остаётся плёнка). Пара «черновая с припуском → чистовая» повторяет заводскую `RADIYS_1_PR0.5` → `RADIYS_1_CHIST`. На 003 два скругления R5: 1 430 → 204 мм рабочего хода при сверке 0/0 и остатке на самих скруглениях 0.10 → 0.00 мм³ |
| `FILLET_TOLERANCE` | `0.01` | мм | стрелка прогиба при ломке дуги сечения; она же задаёт гребешок между строчками чистового прохода |
| `FILLET_FINISH_FEED` | `0.5` | доля | подача ЧИСТОВОГО прохода по скруглению как доля `FEED_RATE`. Заводское значение: `RADIYS_1_CHIST` режет на F1000 при F2000 на всех остальных операциях (плюс F800 на переходах между строчками и F600 на первом подводе — у нас переходы идут отводом по воздуху, поэтому нужен только основной множитель). Это решение про ШЕРОХОВАТОСТЬ, а не про нагрузку: радиальная нагрузка на чистовом проходе как раз мизерная, и вывести множитель из геометрии нельзя. Черновой проход по скруглению остаётся на полной подаче, как заводская `RADIYS_1_PR0.5`. На 003: машинное время 00:03:25.4 → 00:03:30.4 при заводских 00:03:29.96, геометрия не меняется. `1.0` = не сбрасывать |
| `FACE_MEDIAN_LINE` | `true` | — | чистовой проход по УЗКОЙ ПЛОСКОЙ полосе — одной линией по её середине (`Path.Op.Engrave`), а не 3D-сканом. Полосой считается зона, у которой меньшая сторона габарита не больше двух Ø фрезы и площадь занимает ≥ 75 % габаритного прямоугольника (тот же признак, по которому работает стадия съёма объёма). Замер на верхнем торце стенки 003 (полоса 2.5 × 30.4 мм): 3D-проход кладёт девять строчек по зоне шириной 24 мм, из них четыре крайние — 179 мм из 472 — не дотягиваются до стенки вовсе, и каждая строчка вдвое длиннее полосы. Стало 39 мм при неизменной сверке. Только для ПЛОСКИХ граней: у кривой средняя линия задала бы плоский рез |
| `ROUGH_MODE` | `"stages"` | — | `stages` = по типам фич; `layers` = послойно, как Cavity Mill (эксперимент, `--rough-mode layers`) |
| `ROUGH_ALLOWANCE` | `0.5` | мм | **величина припуска** (шаг 0.1). `0` = черновая выключена |
| `ROUGH_ALLOWANCE_MODE` | `none` | — | где оставлять припуск: `none` начисто / `xy` стенки / `all` везде (флаги `--allowance-xy` / `--allowance-all`) |
| `ROUGH_STEPDOWN` | `1.0` | мм | слой съёма за проход (главный рычаг времени обработки) |
| `EVEN_STEPDOWN` | `true` | — | раскладывать слои по высоте РОВНО. FreeCAD делит высоту на шаг с округлением вверх, и остаток становится отдельным уровнем, каким бы малым он ни был: у обвода контура 003 высота 2.016 мм при шаге 1.0 давала ТРИ уровня, из которых третий снимал **16 микрон** — целый обвод детали (270 мм) ради них, и так дважды, черновым и чистовым. Ровная раскладка даёт два слоя по 1.008: 6 витков вместо 4, как у завода. Заданный шаг при этом может быть превышен, но не более чем на 5 % — ровно настолько, насколько дешевле превысить, чем гнать лишний проход. На 003: 6 140 → 5 611 мм рабочего хода, ISV 00:04:24 → 00:04:08, сверка не изменилась ни на сотую даже на строгих порогах |
| `HOLE_POCKET` | `true` | — | сквозные вырезы выбирать ВИТКАМИ ПО КОНТУРУ (follow periphery), как заводской `CAVITY_MILL`, а не трохоидами `Path.Op.Adaptive`. Виток идёт по контуру зоны, отжатому на радиус + припуск, следующий — внутрь на шаг строчки. Если зону накрывает ОДИН виток (вписанная окружность зоны не больше 2R + припуск), ставится один контурный проход: выборка FreeCAD кладёт витки, пока не выродится ЛИНИЯ центра фрезы, а не пока остаётся непокрытое, и на окне 003 добавляет второй виток 64 мм на уровень впустую. Adaptive остаётся запасным путём: постоянная нагрузка нужна там, где виток шёл бы полной шириной по глубокому слою. Замер по 12 фрезерным деталям: у 11 окно накрывается одним витком (вписанная 8.0…12.0 при достижимых 12.5), у 019 нужны витки (13.5). На 003: выборка окна 522 → 192 мм, кадров 505 → 47, сверка 0/0 без изменений |
| `ROUGH_STEPOVER` | `85` | % Ø | шаг между строчками **на одном слое** (выборка плоскостей и вырезов): 85 % = фреза берёт почти всю ширину, змейки на слое минимум. Меньше = больше проходов и времени |
| `ROUGH_STEPOVER_SLOPE` | `40` | % Ø | то же для наклонов/радиусов (террасы Path Surface): там гребешки между строчками остаются на самой детали, поэтому шаг мельче. **Действует только когда чистового прохода нет.** С `FINISH` и припуском гребешки ложатся в припуск и снимаются чистовым, поэтому черновой по граням идёт крупным шагом `ROUGH_STEPOVER` — на 003 это 3 225 → 1 667 мм при той же сверке |
| `ROUGH_TOLERANCE` | `0.1` | мм | точность расчёта траектории; для черновой 0.2 — быстрее почти без потерь |
| `FINISH` | `false` | — | чистовой проход после каждой черновой (`--finish`): по граням — один проход Path Surface прямо по поверхности, по вырезам и внешнему контуру — контурный обход с нулевым смещением. Имеет смысл только вместе с припуском: без него черновая уже режет начисто |
| `FINISH_STEPOVER` | `25` | % Ø | шаг строчек чистового прохода — мельче чернового: гребешки между строчками остаются на самой детали |
| `SURFACE_KEEP_INSIDE` | `false` | — | запирать ли 3D-проход по наклону внутри границы грани. `false` (дефолт) — фреза выходит за кромку и грань обрабатывается целиком; `true` убирает зарез соседней стенки, но оставляет вдоль края полоску шириной в радиус фрезы (лечится фрезой помельче) |
| `SURFACE_BOUNDARY_ENFORCE` | `true` | — | соблюдать ли границу 3D-прохода. Граница расширена на радиус фрезы, поэтому край грани покрывается полностью и при соблюдении. `false` — прежнее поведение: сканирование идёт по габариту ЗАГОТОВКИ, и строчки, целиком лежащие вне грани, опускаются на дно прохода и режут БОКОМ всё, что стоит на пути. Замер по всем 12 деталям: десять не изменились, 023 4015 → 3899 мм при сверке 0/0, 025 14827 → 6245 мм и 00:09:39.85 → 00:04:29.39 при зарезе 3.6 → 0 и недорезе 34.6 → 51.0 |
| `SKIP_FORMED_FACES` | `true` | — | не заводить операции на грани, которые УЖЕ готовы в заготовке (радиус гиба у гнутого листа, литые и кованые поверхности). Припуск меряется по САМОЙ поверхности грани, точка за точкой, а не по низу её габарита: у кривой грани собственная высота габарита — не припуск. На 003 снимает пару операций на радиус гиба (1 370 мм рабочего хода, машинное время 00:05:14 → 00:04:21 при неизменной сверке 0/0) |
| `FORMED_FACE_TOL` | `0.05` | мм | порог: заготовка нигде не выше поверхности грани больше чем на столько — грань считается готовой. Стоит в пустом промежутке: на всех 12 фрезерных деталях КнААЗ пропускаемая грань даёт ровно 0.00, а минимум по оставленным — 1.00 мм |

### 3a. Подходы, врезания и порядок перемещений

Требования ОЭЦМ КнААЗ к безопасности программы. Все три параметра работают
пассом по готовому G-коду, поэтому одинаково действуют в любом диалекте.

| Параметр | Дефолт | Ед. | Что означает |
|---|---|---|---|
| `TOOL_CATALOG` | `{12.0: …}` | — | паспорт фрезы по диаметру (обозначение, радиус при вершине, длина режущей части, вылет, длина сборки) — печатается комментарием в строке вызова инструмента. Чего нет в каталоге, печатается как «?» |
| `SAFE_START_ORDER` | `true` | — | после смены инструмента сначала XY на высоте смены, потом опускание по Z (как в заводских программах). `false` = как отдаёт FreeCAD: сначала Z, потом XY |
| `AIR_PLUNGE_RAPID` | `true` | — | делить отвесный спуск на холостую часть (до верха материала) и рабочее врезание. Верх материала считается по модели снятого металла: карта высот заготовки, которую фреза опускает по ходу программы |
| `AIR_PLUNGE_CLEARANCE` | `1.0` | мм | где холостой ход останавливается над металлом |
| `RAMP_ANGLE` | `20.0` | град | врезание рампой «змейкой» вдоль отрезка, который фреза всё равно сейчас режет. `0` = отвесный вход на вертикальной подаче. Путь врезания = глубина / tg(угол), поэтому пологая рампа безопаснее и длиннее |
| `AIR_CUTS_RAPID` | `false` | — | переводить в холостой ход и горизонтальные рабочие ходы выше материала. Выключено намеренно: лишний спуск по воздуху безвреден, а ошибочно пропущенный рез оставит металл на детали |
| `DROP_NULL_MOVES` | `true` | — | выбрасывать кадры, которые никуда не ведут (цель совпадает с текущей точкой). Замечание ОЭЦМ «повторяющийся код»: операции FreeCAD начинаются отводом на плоскость безопасности и им же заканчиваются, а Engrave печатает отвод дважды и внутри одной операции; стойка отрабатывает такой кадр как паузу. Считается не «строка равна предыдущей», а «кадр без движения», поэтому ловится и `G0 X10 Y20` следом за `G0 X10 Y20 Z5`. G2/G3 не трогаются: у полной окружности начало совпадает с концом |

Замер на детали 003 (`--stock ..._zag_oriented.stp --stock-align`, одна фреза Ø12):
отвесных врезаний в металл **430 → 0**, «вниз по Z, потом вбок» **1 → 0**, машинное
время в NX ISV **00:32:40 → 00:31:01**, сверка с моделью 0 / 0 в обоих случаях.
Программа стала И безопаснее, И короче: спуски по воздуху перестали идти на рабочей
подаче, а рампы за это заплатили меньше, чем сэкономили спуски.

Посчитать эти величины для любой программы: `python cam/gcode_stats.py out.gcode`
(несколько файлов — таблицей для сравнения, `--list` — поимённо).

### 4. Проверка результата (diff «деталь vs симуляция»)

| Параметр | Дефолт | Ед. | Что означает |
|---|---|---|---|
| `DIFF_PITCH` | `0.1` | мм | шаг воксельной сетки. Это **предел разрешения**: дефект тоньше шага проверка не видит в принципе. `0` = авто (крупная сторона / 110 ≈ 0.7 мм — грубо) |
| `DIFF_MIN_VOLUME` | `0.2` | мм³ | зоны мельче отбрасываются как шум фасетизации тела симуляции |
| `DIFF_MIN_THICKNESS` | `0.2` | мм | **допуск по толщине**: расхождение тоньше не считается дефектом. Без него мелкая сетка даёт сотни мм³ фантомного «зареза» ровным слоем по всей полке — тело симуляции фасетное, его хорда смещает каждую обработанную поверхность на ~0.1 мм |
| `DIFF_OK_UNDERCUT_MM3` | `1.0` | мм³ | порог остановки ЛЛМ-петли по недорезу: ниже — результат принят |
| `DIFF_OK_OVERCUT_MM3` | `0.0` | мм³ | то же по зарезу: требование жёсткое — зарез неисправим, снятый металл не вернуть |

### 5. Вывод и система

| Параметр | Дефолт | Что означает |
|---|---|---|
| `ORIGIN` | `"corner-bottom"` | ноль программы: `corner-bottom` — X0 Y0 в углу габарита детали, Z0 = НИЗ (ноль заказчика: на карте эскизов КнААЗ ось Z построена от плоскости стола вверх, и во всех шести заводских программах ход по Z целиком в плюсе); `center-bottom` — X0 Y0 в центре; `corner-top` / `center-top` — то же с нулём по верху (прежний дефолт); `model` — не сдвигать (как в CAD-файле). Детали из NX часто экспортированы в координатах сборки — без нормализации фреза уедет «в бок» на первое же перемещение |
| `POSTPROCESSOR` | `"grbl"` | диалект G-Code под контроллер: `grbl`, `linuxcnc`, `fanuc`, `mach3_mach4`, `marlin`, `smoothie`, `heidenhain`, `centroid`, `uccnc` и др. |
| `EMIT_HEIDENHAIN` | `true` | класть рядом с `<out>.gcode` программу для заводской стойки — диалог Heidenhain `<out>.h` для iTNC 530 на DMC 635V. Переводит `nx/grbl_to_heidenhain.py`; ноль по Z берётся из `ORIGIN`, так что оба файла выходят в ОДНОЙ системе координат и отдельный шаг сдвига не нужен. Флаг CLI: `--no-heidenhain` |
| `HEIDENHAIN_NAME` | `""` | имя программы у стойки в `.h`; пусто → из имени файла. Флаг CLI: `--h-name` |
| `HEIDENHAIN_TOL` | `0.01` | мм — допуск линеаризации дуг при переводе в `.h` |
| `FREECAD_CMD` | `""` | путь к `freecadcmd`; пусто = автопоиск (Windows: `Program Files`/`%LOCALAPPDATA%\Programs`; Linux: AppImage → PATH → snap) |
| `FREECAD_TIMEOUT` | `3600` | сек — лимит на расчёт траектории (черновая Adaptive на сложной детали считается десятки минут) |
| `NX_BASE_DIR` | `""` | корень установки Siemens NX (папка с `NXBIN`) — только для входа `.prt`; пусто = автопоиск (`UGII_BASE_DIR` → `C:\Program Files\Siemens\NX*`) |
| `NX_STEP_AP` | `"242"` | версия STEP при экспорте из NX: `203` / `214` / `242` |
| `NX_TIMEOUT` | `600` | сек — лимит на конвертацию `.prt` → STEP |
| `STL_SCALE_TO_MM` | `1000.0` | **только для мешей**: множитель единиц → мм (Blender-метры = 1000, CAD-мм = 1.0). Для STEP/IGES игнорируется |

### Пример `config.yaml` под задачу

```yaml
TOOL_DIAMETER: 4.0          # фреза, которая реально стоит в шпинделе
FEED_RATE: 600              # подача под материал
SPINDLE_SPEED: 18000
POSTPROCESSOR: "linuxcnc"   # диалект вашей стойки
ROUGH_STEPDOWN: 0.8         # слой съёма за проход
```

## Что проверить перед станком

1. **Габариты** — размеры траектории соответствуют модели.
2. **Симуляция** — прогнать в [CAMotics](https://camotics.org) или
   [ncviewer.com](https://ncviewer.com): траектория, глубины, отсутствие зарезов.
3. **Диалект** — `POSTPROCESSOR` соответствует контроллеру станка.
4. **Ноль детали** — по умолчанию (`ORIGIN: corner-top`) X0 Y0 = левый-ближний угол
   габарита детали, Z0 = её верхняя плоскость; выставить ноль на станке соответственно.
5. Контроля столкновений и зарезов **нет** — ответственность на операторе.

## Ограничения

- 3-осевая обработка сверху: поднутрения, обратная сторона, боковые элементы недоступны.
- Обрабатывается то, что «видно сверху»; вертикальные стенки получаются проходами строчек.
- Только черновая по этапам — отдельного чистового (финишного) прохода нет.
- Крепёж/оснастка не моделируются; заготовка = габарит модели.
- `.prt` без установленного NX требует ручного экспорта STEP из NX (открытых
  конвертеров не существует); с установленным NX конвертация автоматическая.

## Как это устроено внутри

- `run_cam.py` — CLI-обёртка.
- `cam/freecad_cam.py` — хост: находит `freecadcmd`, передаёт параметры (JSON через
  env `FREECAD_WORKER_PARAMS`), парсит результат. FreeCAD — отдельный процесс.
- `cam/freecad_worker.py` — исполняется внутри FreeCAD: модель → тело → Path Job
  (заготовка + фреза) → операции → постпроцессор → G-Code.

Установка FreeCAD (AppImage, без root) и быстрый старт — в основном [README.md](README.md).
